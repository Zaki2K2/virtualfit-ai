# API documentation

Base URL: `http://localhost:5000/api/v1` (or `/api/v1` through the web app). Identity is a server-set `vf_guest` cookie; clients send cookies automatically.

Errors: `{ "error": { "code": "...", "message": "...", "details"?: ... } }`. Codes: `VALIDATION_ERROR`, `UNSUPPORTED_IMAGE`, `FILE_TOO_LARGE`, `NOT_FOUND`, `CONSENT_REQUIRED`, `AI_UNAVAILABLE`, `AI_QUOTA_EXHAUSTED`, `AI_TIMEOUT`, `AI_FAILED`, `RATE_LIMITED`, `DATABASE_UNAVAILABLE` (503, MongoDB unreachable), `INTERNAL_ERROR`.

## Local language styling assistant

This is separate from `/try-on` vision inference and does not use `AI_PROVIDER`.

- `GET /api/v1/styling/status`: actual local runtime/model availability, provider `llama-cpp`, model alias, local processing and customization method. Returns 200 with `available: false` if the language runtime is absent; it does not fabricate inference.
- `POST /api/v1/styling/recommend`: guest-scoped recommendation. Body is strict JSON `{ "message": "Casual white top and khaki trousers, no dresses." }`; message length 3�600 after trimming. Response contains `answer`, `itemIds`, `occasion`, model-interpreted `categories`, resolved `items` (existing ClothingItem DTOs), `model`, and `simulated: false`.

Only the guest's accessible clothing is retrieved. A shortlist of 12 bounded text descriptions and preferred categories is sent to authenticated loopback inference; measurements, photos and image URLs are omitted. Explicit English category exclusions are applied before inference. Generated IDs are schema-constrained and checked again against the shortlist; no arbitrary database lookups are performed from model instructions. The prose and category interpretation can still be wrong; this is experimental styling advice, not size/fit guidance.

Errors: 400 validation, 422 no candidate clothing after filtering, 429 request/concurrency limit, 503 runtime unavailable, 504 inference timeout, 502 malformed/truncated/ungrounded model output. Dedicated limit: 30 requests/IP/hour, separately from vision; one active request per API process. Inference response size is bounded at 32 KiB and no redirects are followed. No conversation/history collection is added. Start with `npm run slm:setup`, then `npm run slm:serve`, or run the combined stack using `npm run dev:slm`. Model setup and training: [slm-engine/README.md](../slm-engine/README.md).

### Phase 3 styling protocol

`POST /styling/recommend` also accepts optional `model: "base" | "custom"`. Custom requires a trained, loaded and registered checkpoint; requests never silently switch models. `GET /styling/status` includes `models` with independent availability/reasons.

Results include `source` (`model`, `deterministic-fallback`, `catalog-policy`), `modelUsed`, `fallbackReason`, parsed `intent`, and `diagnostics` with raw schema/selection validity and candidate IDs. Model schema or preference violations produce an explicitly labeled deterministic selection; runtime outages, timeouts and genuine internal errors still fail. Every validated language request now invokes local Qwen, including category questions, general color advice, unsupported inventory and clarification; empty selections remain constrained by verified inventory rules. Attribute filters precede ranking and inference; candidates come only from the existing ownership-aware clothing service (MongoDB uploads plus bundled catalog). See the Phase 3 report for assumptions about inferred metadata and narrow English parsing.

### Current local language hosting

Run `npm run dev:ai` for Qwen on loopback 8081, Express on 5000 and Next.js on 3000. `GET /api/v1/styling/status` verifies real generation (cached for up to 30 seconds) and reports `inferenceVerified`, `checkedAt` and the model display name. `/health`'s existing `ai` block describes the separate vision provider.

`POST /api/v1/styling/recommend` accepts `{message, model?: "base"|"custom", history?: string[]}` with at most two prior user requests. Every valid language request now invokes the local SLM, including category questions, general color advice and no-match replies. Express resolves follow-up constraints against a fresh permitted wardrobe; raw prior messages are not forwarded to Qwen. Numeric body measurements, photo payloads and unknown request fields are rejected. Models never receive image URLs or body profile fields.

`source: model` means the model response passed validation. Invalid output returns `source: deterministic-fallback` with a reason, including `ungrounded-explanation` when prose introduces garments beyond the selected inventory. Diagnostics include `rawExplanationValid`. Outages and timeouts remain explicit errors. The legacy `catalog-policy` source remains in the response type for compatibility; the current path no longer uses it to bypass Qwen. No raw llama.cpp administration route is proxied through Express. See [local hosting and verification](local-slm-hosting.md).
